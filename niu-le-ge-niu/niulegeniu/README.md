# 牛了个牛 ·《牛来》联动版 v3.1 🐮

单文件 HTML5 三消小游戏（「羊了个羊」式玩法），电影《牛来》联动主题。
**零依赖 · 离线可玩 · 手机 / 平板 / 桌面全适配 · 全部素材内嵌单文件**

---

## 一、快速开始

| 使用方式 | 操作 |
|---|---|
| 本地游玩 | 双击 `index.html`，用任意现代浏览器打开 |

## 二、玩法说明

### 基本规则
1. **目标**：清空棋盘上的全部方块。
2. **操作**：点击**亮起的**方块 → 收入底部卡槽；卡槽中集齐 **3 张相同图案**立即自动消除。
3. **失败**：卡槽被占满且未能凑齐消除 → 本局结束。
4. 变暗的方块 = 被上层方块压住，不可点击；上层拿走后会自动亮起。

### 隐藏重叠井（核心特色）
- 棋盘中部埋着若干「井」：**多张方块压在同一坐标**，井口你只能看到最上面一张。
- 拿走后**同一位置会立刻露出下一张** —— 井有多深，不玩到那一层永远不知道。
- 井的数量与深度**每局随机**，游戏界面刻意不显示任何方块数 / 层数 / 井深信息，保留「越挖越深」的悬念。
- 挖出隐藏牌时有金光弹出特效；挖穿一整层时有氛围提示（但绝不会告诉你还剩几层）。

### 道具
| 道具 | 作用 |
|---|---|
| ↩️ 撤回 | 回退上一步操作（回到上一次点击前的状态） |
| 🔀 洗牌 | 重新打乱场上剩余方块的图案 |
| 💊 复活 | 游戏中：把卡槽里最多 3 张牌放回牌堆；失败时：清空整个卡槽继续 |

### 彩蛋
- 点击标题下方的**牛头方块**：牛来会喊「牛来，妈妈~~~」。
- 每完成一次三消，棋盘上飘出「牛来，妈妈~~~」台词。
- 通关时天降牛牛雨 🐮🎉

## 三、难度体系

| 难度 | 牌堆 | 卡槽 | 撤回 / 洗牌 / 复活 | 咬合 | 隐藏井 | 特殊 |
|---|---|---|---|---|---|---|
| 极简模式 | 2 层 / 15 块 | 7 格 | ×3 / ×3 / ×1 | 半格 | 无 | 轻松一局 |
| 简单 | 5 层 / 108 块 | 7 格 | ×5 / ×5 / ×2 | 半格 | 无 | — |
| 中等 | 6 层 / 117 块 | 7 格 | ×3 / ×3 / ×1 | 深层咬合（1/4 格） | 无 | 开始上强度 |
| 困难 | 8 层 / 135 块 | 6 格 | ×2 / ×2 / ×1 | 深层咬合 | 3-4 口（含 1 口深井 6-8 张） | 祝你好运 |
| 地狱难度 🔥 | 9 层 / 189 块 | 7 格 | ×1 / ×1 / **×0** | 更深咬合 | 3-4 口（含 2-3 口深井 **15-20 张**） | 隐藏剩余方块计数 · 佛祖保佑 |

> 表中参数属于游戏内部设定；**游戏界面刻意不展示这些数字**，以保留挖牌悬念。所有难度总牌数均为 3 的倍数，保证理论可解。

## 四、代码架构说明

### 整体结构
单文件 `index.html`，由三部分组成：

```
<style>   全部样式（含手机/平板媒体查询）
<body>    页面骨架：header(标题/统计) + 棋盘 + 卡槽/道具 + 弹窗 + toast
<script>  游戏逻辑（单个 IIFE，约 600 行原生 JS，无任何第三方库）
```

### 图片资源
所有图像均以 **base64 data URI** 内嵌，运行期**零外部请求**：
- `SHEET_URI`：九宫格角色贴图（牛来 / 云雀 / 小绳头 / 豹拉 / 草原 / 梦境 / 星光 / 爱心 / 成长）
- 牛来大脸图：单独一张（方形大图，方块与标题牛头共用）
- 图片缺失时自动回退到 emoji 显示（`body.no-sheet` / `body.no-lai` 兜底样式）

### 渲染方式
- 纯 DOM 绝对定位（无 Canvas / WebGL），每张方块是一个 `<div class="tile">`，用 `left/top/z-index` 定位。
- 方块最大规模约 189 个 DOM 节点，性能开销可忽略。

### 核心数据模型
```js
tiles[] = {
  id,            // 唯一编号
  type,          // 图案（emoji 字符，作为类型键）
  layer,         // 所在层号（决定遮挡与 z-index）
  gx, gy,        // 该层网格坐标（列/行）
  jx, jy,        // 随机抖动像素（让牌面有自然感）
  pos,           // 重叠井覆盖：{layer,gx,gy,jx,jy}，把牌压到堆底格子
  x, y,          // 计算后的像素坐标（响应式重排时更新）
  el,            // DOM 引用
  taken          // 是否已被拿走
}
tray[]           // 卡槽内的方块引用（最多 slots 个）
snapshot         // 撤回快照：{ tray: [id...], taken: [bool...], steps }
```

### 响应式布局（重点）
早期版本用 `transform: scale()` 缩放棋盘，会导致布局盒与视觉盒不一致、窄屏偏移。v3 起改为**真响应式**：

1. `computeUnit(diff)`：按视口直接算出牌尺寸
   ```js
   TILE  = clamp(28, min(宽约束, 高约束), 56)   // 宽约束 = (min(屏宽,640)-16-10) / ((最大列数-1)*1.107 + 1.5535)
   PITCH = round(TILE * 1.107)                  // 牌间距与牌尺寸等比
   ```
   同时写入 CSS 变量 `--tile`，方块与卡槽尺寸自动跟随。
2. `tileXY(t)`：由「网格坐标 + 层错位 + 抖动」推算像素位置（井牌用 `pos` 覆盖到堆底格子）。
3. 窗口尺寸变化（`resize`）→ `layoutBoard()` 重算尺寸 → `repositionTiles()` 重排所有牌 → `updateSelectable()` 重算遮挡 —— 转屏/拉窗口即刻自适应，无需刷新。

### 关键函数一览
| 函数 | 职责 |
|---|---|
| `build(dKey)` | 开局：按难度取层配置 → 分配图案 → 生成金字塔 → 建井 → 重排 → 绑定点击 |
| `buildWells(diff)` | 生成隐藏重叠井：堆底取第 0 层中部随机牌（用「2 格 → 1 格 → 不限」三级间距保证分散），成员池为所有上层牌洗乱后依次压入；`megaCnt` / `megaDepth` 控制深井数量与深度 |
| `isBlocked(t)` | 遮挡判定：存在层号更高、且像素距离小于牌宽的牌 → 被压住 |
| `pick(t)` | 点击主流程：入槽 → 三消判定 → 挖出隐藏牌特效 → 挖穿提示 → 结束判定 |
| `resolveTray()` | 三消：卡槽中出现连续 3 张同图案即消除并加分 |
| `undo / shuffle / reviveBar / reviveAll` | 三件道具的逻辑 |
| `checkEnd()` | 胜负判定：卡槽满 → 失败；全清 → 通关 |
| `updateSelectable()` | 刷新所有方块的「可点/被压」状态与样式 |

### 图案与可解性设计
- 图案按「**3 张一组循环分配**」：把总牌数分成 N/3 组，每组塞入同一种图案，再全局洗乱。
- 由此保证**每种图案的数量必为 3 的倍数** —— 这是「理论可解」的必要条件（实际能否通关仍取决于出牌顺序与运气）。
- 各难度总牌数均为 3 的倍数（15 / 108 / 117 / 135 / 189）。

### 状态与存储
- 全部为内存态，**不使用 localStorage**：刷新页面即回到难度选择，不保留进度。
- 计时器：`setInterval` 每秒刷新已用时间。

## 六、兼容与适配

- **浏览器**：iOS Safari / Android Chrome / Edge / Chrome / Firefox / Safari（需支持 CSS 变量、flex、`clamp()`/`min()`）
- **手机适配要点**
  - 牌尺寸按视口动态计算，320px 超窄屏到桌面宽屏同一套代码自适应
  - `viewport-fit=cover` + `env(safe-area-inset-bottom)`：刘海屏 / 全面屏底部安全区
  - `touch-action: manipulation`：消除移动端点按延迟与双击缩放
  - `≤600px` 媒体查询：标题、统计栏、弹窗、道具按钮整体紧凑化；隐藏方块名字小标签
  - 标题字号使用 `clamp()`，窄屏自动收缩，保证「牛头 + 标题」始终完整居中
- **平板 / 桌面**：棋盘宽度上限 624px，居中显示，牌尺寸上限 56px

## 七、开发与构建

本项目的迭代方式（构建管线）：

```
原版 index.html  ──┐
                   ├──> 构建脚本 _transform31.js ──> 牛了个牛3.1.html
改动规则（16 条）──┘
```

- 构建脚本以「原版文件 + 定向文本替换」的方式生成成品，每条替换都会**校验唯一匹配 + 逐条即时验证**，最后做 JS 语法校验（`vm.Script`）。
- 若要二次开发：修改 `index.html` 本体，或在脚本中调整对应替换规则后重新生成。
- 构建脚本与校验日志属于开发工具，**部署时不需要上传**。
